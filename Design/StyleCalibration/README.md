# 風格校色：第四輪暗部細節與噪點

## 範圍與結果

使用六張公開攝影作品，比較全部 12 種內建風格，每輪產生 72 張風格輸出；保留最初版本、第一輪、第二輪、第三輪與目前第四輪，共 360 張風格輸出。樣本涵蓋窗邊自然光人像、棚燈人像、日間湖景、咖啡館室內、台北夜間街景與海灘夕陽。兩張人像另作人工視覺檢視。第三輪新增依像素色彩估計的柔和保護遮罩，不做人臉辨識，也不聲稱涵蓋所有膚色。

這是小型公開樣本集上的主觀風格調校，不是 iPhone 實拍、RAW／色卡校正、Apple 照片演算法比對，亦非特定底片的復刻。來源 JPEG 可能已經攝影者調整；棚燈人像是歷史攝影作品，不能作為現代手機的色彩標準。未驗證的情境包括不同 iPhone、HDR、逆光膚色、混合色溫與高 ISO 噪點。

開啟 `comparison.html`，可切換六個場景與 12 種風格，選擇最初版本或前三輪作為比較基準，並排看原圖、先前版本、第四輪與參數／像素差異。點圖片可開啟完整尺寸。`*-before-sheet.jpg`、`*-after-sheet.jpg` 是每場景的完整風格縮圖。編號 01–12 依序為復古、暖調底片、日系清透、電影、經典黑白、柔光人像、夕陽、冷調、鮮明、霧感、城市街拍、咖啡暖棕。

## 第四輪：暗部細節與噪點

本輪保留 12 款風格數值，改變共同的影像處理。先在原始圖像上抑制噪點，再做曝光、陰影、色彩與後續銳化；移除原本調色後再全圖降噪的重複步驟。

- 正向陰影／增艷提亮時，自動加入有上限的暗部降噪。暗部權重隨亮度平滑下降，到 sRGB 編碼亮度 0.55 即歸零；亮處不套自動平滑。
- 色彩噪點與明暗紋理分開重組：用窄範圍色彩鄰域減少彩色顆粒，保留大部分原始明暗訊號；強明暗邊緣與色彩邊界減弱處理。自動色彩混合最高 60%，明暗混合最多為其 40%（24%），還會乘上暗部及邊緣權重。
- 手動「降低雜點」保留 0–100 範圍，也可作用於亮部，並增加明暗降噪。設為 0 表示沒有額外手動降噪；正向陰影觸發的基礎保護仍會運作。全零原色直接保留原圖。
- 陰影曲線在一般暗部稍加強層次分離，靠近純黑時減少提亮，避免一起抬高黑位與最低訊號的顆粒。純黑維持黑；不聲稱能重建原圖沒有的細節。

這是固定強度、依亮度／邊緣加權的單張影像處理，並沒有估測感光元件噪點、讀取 ISO 或作多幀合成。半徑以像素計算，因噪點是像素層級訊號；不同解析度與實際取景／成片的噪點分布仍須真機檢查。相近低對比紋理與噪點難以完全區分，保留細節與乾淨程度之間仍有取捨。

### 可重現的噪點檢查

另附 [合成噪點對照](shadow-noise/comparison.jpg) 與 [測量資料](shadow-noise/metrics.json)。固定亂數種子，在幾何暗部測試圖、既有窗邊人像及台北夜景上加入已知噪點，再由第三輪／第四輪的實際 Swift JPEG 輸出流程處理。幾何圖使用陰影 +60；兩張照片使用「電影」風格。這些是壓力測試，**不是新的真實高 ISO 照片**。

誤差對照每一版本各自的乾淨輸出，避免把版本間的色調差當作噪點；使用原圖亮度 8–70 的固定遮罩，計算明暗與色彩殘差 RMSE（0–255 編碼值）。檢查要求三組色彩誤差各降低至少 5%，明暗誤差至多增加 2%；此外單元測試要求平坦暗部誤差減少、無明顯亮度偏移、乾淨細紋振幅保留超過 90%、邊緣反差保留超過 95%。這些界限是本次回歸標準，不是通用畫質分數。

最終 37 項單元測試（5 群組）通過，包含本輪新增 4 項暗部／噪點測試；軟體與預設渲染器一致性測試也已涵蓋降噪。72 組照片通過既定像素檢查。三組固定噪點的最終結果：

| 樣本 | 色彩 RMSE | 明暗 RMSE |
|---|---|---|
| 合成暗部測試圖 | 1.478→1.192（降低 19.3%） | 5.082→4.435 |
| 人像加噪樣本 | 1.258→1.193（降低 5.2%） | 3.847→3.527 |
| 夜景加噪樣本 | 1.590→1.501（降低 5.6%） | 4.110→3.795 |

以上誤差下降僅適用本次合成噪點樣本，不能推論真機高 ISO 的改善百分比。

重新渲染自訂配方也會使用新流程；配方數值、風格 ID、原圖及已儲存照片檔案不改寫。前三輪的膚色保護與亮部壓縮仍保留。

## 第三輪：膚色與亮部過渡

本輪維持全部 12 款風格的第二輪參數，修改共同的 `RecipeColorPipeline`，讓預覽、拍照輸出與重新編輯使用相同處理。

### 膚色範圍保護

在原始輸入的 sRGB 編碼色彩上，以紅／橘色相、飽和度與亮度建立平滑權重，涵蓋不同明暗的暖色像素。這不是人臉、人物或膚色身分辨識；木材、沙地、橘色物體也可能符合，混合色光下的皮膚則可能漏掉。

色溫／色調，以及正向飽和度／自然飽和度的增量，在遮罩最強處減少 55%，仍保留 45% 的風格色彩改變；過渡區減弱保護。亮度與曝光不被膚色遮罩拉回，負向飽和度不被抵銷，因此黑白仍能完全去色。遮罩使用原始色彩，避免風格染色後才將非膚色選入。55% 是本次人工選擇的折衷，不是經過廣泛人像資料集驗證的通用係數。

### 亮部過渡

負向亮部與增艷的亮部保護改用單調的有理壓縮曲線，接合處數值與一階斜率連續；避免舊二次增益在極端組合下出現更亮的灰階反而更暗的情況。亮度依同一比例縮放 RGB，減少逐通道硬剪裁帶來的色偏。

調色完成後，在非常明亮的區域再依最大 RGB 通道作柔和壓縮，避免色溫、飽和度把紅／藍通道推到輸出上限。這個尾段只在負向亮部或正向增艷啟用，原色零參數仍直接保留來源。它保留過渡但會讓最亮的白色稍暗，無法重建原始 JPEG 已剪掉的細節。

### 驗證與影響範圍

最終 33 項單元測試（5 個測試群組）及全部 72 組像素檢查通過，包含新增的 5 項成像回歸測試。局部放大檢視棚燈人像與湖景雪山，另檢視六場景整組風格對照。第二輪到第三輪的樣本數據：

- 夜景／鮮明：新增高亮通道剪裁 0.04569%→0.02149%。
- 夜景／夕陽：新增高亮通道剪裁 0.02347%→0.00861%。
- 湖景／鮮明：新增高亮通道剪裁 0.00756%→0.00404%。

比例僅描述這幾張樣本，不等於膚色色準或通用畫質分數。

- 六場景、12 風格重新輸出 72 張，與第二輪固定輸入比較，同時保留更早版本。
- 新增合成暖色塊、灰階漸層、接合處連續性、色彩比例、黑白、原色與軟體／預設渲染器一致性測試；合成色塊不是人像代表性資料集。
- 這次改善引擎，因此既有自訂配方若重新渲染也會採新效果；配方數值、識別碼及既有照片檔案不改寫。
- 測試環境為 macOS Core Image 與 iOS 模擬器；尚未驗證真機畫面、各機型效能、HDR 色彩或所有膚色。核心使用可同時測試軟體與預設渲染器的 CIKernel 相容介面，Xcode 會提示其來源字串 API 已棄用；後續可遷移到預編譯 Metal 核心，但這輪沒有把未量測的效能當作改善成果。

## 第二輪：針對五款風格微調

沿用相同六張輸入，避免更換照片混淆差異。檢視六張完整風格比較圖後，針對暖色／鮮明效果與暗部作小幅修正。其餘七款維持第一輪數值；效果取捨仍屬人工視覺判斷。

| 風格 | 第一輪 → 第二輪 | 目的 |
|---|---|---|
| 電影 | 黑點 10→8、陰影 14→20、暈邊 16→12 | 減輕衣服、牆面與畫面邊緣壓暗，保留冷色與反差 |
| 柔光人像 | 色溫 6→4、陰影 16→22、亮部 −18→−20 | 降低暖色偏移、輕提陰影，同時壓住明亮背景 |
| 夕陽 | 色溫 32→26、色調 6→4、自然飽和度 12→10、飽和度 4→2 | 減少已有暖光照片的橘色疊加 |
| 鮮明 | 飽和度 18→12、自然飽和度 16→18 | 降低整體濃色，保留風景的鮮明特色；不聲稱自動保護膚色 |
| 城市街拍 | 黑點 14→12、陰影 12→18 | 保留俐落對比並增加陰影可讀性 |

初次候選曾把柔光人像亮度 3→4；夜景新增高亮通道剪裁達 0.01125%，相對最初版本超過原先 0.01 個百分點容許差，已撤回亮度改動並加強亮部控制。最終沒有放寬檢查界限。

最終樣本數據（第一輪 → 第二輪）：

- 湖景／鮮明：新增高亮通道剪裁 0.01475%→0.00756%。

- 自然光人像／柔光人像：固定暗部遮罩平均值 32.84→33.68，新增高亮剪裁維持 0%。
- 夜景／電影：固定暗部遮罩平均值 27.14→28.48；街拍 24.92→26.14。
- 夜景／柔光人像：剪裁 0.00493%→0.00653%；提亮仍有小幅代價，但通過既定界限。不是每個指標都只會改善。

全部 72 張目前輸出通過剪裁、壓黑檢查，並同時對最初版本及第一輪作回歸比較。另以 iOS 模擬器驗證風格輸出、配方儲存、色階與風格選擇介面。這輪沒有新增照片或真機驗證；不能當作樣本外泛化結果。

## 像素檢查

所有輸入先正規化 EXIF 方向，轉為或假定 sRGB，等比例縮至最長邊 1200 像素並保存 PNG。以專案的 `RecipeAdjustment`、`RecipeColorPipeline`、`StyleAdjustment` 和 `PhotoProcessor` 原始碼在 macOS 編譯，使用同一個 JPEG 輸出流程；沒有用另一套 Python 濾鏡模擬 App。這仍不是 iOS Metal 預覽畫面與實機拍照的直接比對。

`metrics.json` 提供全部 360 張輸出的測量。數值不是美感、色準或風格相似度分數。

- 新增高亮通道剪裁：輸入通道 <250、輸出通道 ≥254 的比例，以全部 RGB 通道數為分母。不是過曝像素比例。
- 新增暗部壓黑：輸入 sRGB 加權亮度 >8、輸出三通道均 ≤3 的像素比例。
- 暗部平均值：在原圖加權亮度 8–64 的固定遮罩中，計算輸出平均加權值。使用 sRGB 編碼值，不是物理光度。
- 本批樣本的檢查界限：新增高亮通道剪裁 <0.1%，新增暗部壓黑 <0.5%；相對最初版本及前三輪，新增高亮通道剪裁及新增暗部壓黑最多容許 0.01 個百分點的差異。這些是本次人工設定的回歸檢查界限，並非通用攝影標準。

第一輪例：湖景／鮮明的新增高亮通道剪裁由約 1.817% 降至 0.015%；湖景／日系由 0.650% 降至不足 0.001%。黑白／室內的新增暗部壓黑由約 0.0357% 降至 0.0026%。不應將這些比例推論至所有照片。

## 重現

需要 macOS、Xcode Swift、可用的 Core Image 圖像處理環境，以及安裝 Pillow、NumPy 的 Python。

```sh
# 已附正規化輸入，只有想重新下載來源時才需要 fetch。
python3 Tools/Calibration/calibrate_shooting_styles.py fetch
python3 Tools/Calibration/calibrate_shooting_styles.py render before
python3 Tools/Calibration/calibrate_shooting_styles.py render round1
python3 Tools/Calibration/calibrate_shooting_styles.py render round2
python3 Tools/Calibration/calibrate_shooting_styles.py render round3
python3 Tools/Calibration/calibrate_shooting_styles.py render after
python3 Tools/Calibration/calibrate_shooting_styles.py report
python3 Tools/Calibration/calibrate_shooting_styles.py check
python3 Tools/Calibration/check_shadow_noise.py
```

`before/` 凍結最初版、`round1/`、`round2/`、`round3/` 分別凍結前三輪程式與配方，重跑對應版本使用該快照；`after/` 每次從目前 App 程式產生。重新下載可能取得來源網站後來更新的版本，請對照 SHA-256。比較頁可離線開啟。
